    08 / METHODS

    How this page works

    • Server-side fetch. api.taskmarket.dev does not allow browser CORS from other sites, so a GitHub Actions workflow runs node scripts/fetch.mjs every hour, fetches the API and commits the resulting JSON into this repo. This page only reads those local files — it makes no API calls from your browser.
    • Endpoints used (base https://api.taskmarket.dev): /api/market/stats?chainId=… · /api/stats/breakdowns?chainId=… · /api/stats/platform-time-series?chainId=…&range=…&bucket=… · /api/stats/activity-heatmap?chainId=…&range=30d&dimension=… · /api/stats/activity-feed?chainId=…&limit=50 · /api/tasks?chainId=…&sort=newest&limit=100&cursor=… (paginated until hasMore is false, both chains, all statuses).
    • Chains. Tempo chainId=4217 and Base chainId=8453. Market stats, heatmaps, feeds and the task lists differ per chain. Verified quirk: the time-series and breakdowns endpoints return identical data for both chain IDs — they are platform-wide, so they are shown once and never summed across chains (summing would double-count).
    • Units. Reward and paid volumes are reported by the API as integer micro-units; this page divides by 1,000,000 and labels the result USDC. A minority of tasks pay in other tokens, so treat the dollar totals as “as reported, in USDC terms” rather than audited cash.
    • Derived views. Distinct posters per week, money flow, posting concentration and lifecycle shares are computed by the fetcher from the raw responses (see scripts/fetch.mjs and data/derived.json). Nothing is estimated or invented; every number traces to an API response committed in data/.
    • Heatmap days. Day rows follow the API’s numbering (0 = Sunday, UTC). Mode × day columns are calendar dates.
    • Privacy. No analytics, no tracking, no cookies. Wallet addresses are shown truncated and no names or identities are attached to them beyond the display names the API itself returns.
    • Source. MIT-licensed, public repo: github.com/Harugreed/taskmarket-visualizer. One-command deploy: git push — GitHub Pages serves this directory and the hourly workflow keeps the data fresh.
